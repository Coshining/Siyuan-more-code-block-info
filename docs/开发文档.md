# 开发文档：代码块更多信息插件

## 1. 环境要求

- Node.js >= 20.11（推荐 20+，`import.meta.dirname` 需要 20.11+）
- npm（已封装进 `scripts/` 脚本）
- 思源笔记 3.8.5+

## 2. 目录结构

```
.
├── plugin.json         插件配置
├── package.json
├── tsconfig.json
├── vite.config.ts      Vite 构建配置
├── icon.png            插件图标（160×160）
├── preview.png         预览图（1024×768）
├── i18n/               国际化
│   ├── zh_CN.json
│   └── en_US.json
├── .github/workflows/   GitHub Actions 自动发布
│   └── release.yml
├── scripts/            启停与构建脚本
│   ├── install.sh / install.ps1
│   ├── build.sh / build.ps1
│   ├── dev.sh / dev.ps1
│   ├── clean.sh / clean.ps1
│   └── clean.mjs
├── src/                源码
├── docs/               正式文档
└── discuss/            讨论文档
```

### 2.1 发布资源约束

- `icon.png`：160×160，不超过 64 KB。
- `preview.png`：1024×768，不超过 512 KB。
- 仅支持 PNG / JPEG / WebP / AVIF，不要使用 SVG。

## 3. 安装依赖

Linux/macOS/WSL：

```bash
scripts/install.sh
```

Windows PowerShell：

```powershell
.\scripts\install.ps1
```

## 4. 构建

```bash
scripts/build.sh        # Linux/macOS/WSL
.\scripts\build.ps1     # Windows PowerShell
```

构建产物：

- `dist/`：插件目录（index.js、index.css、plugin.json、icon.png、preview.png、README、i18n）
- `package.zip`：可发布到集市的压缩包

## 5. 本地调试

### 5.1 热构建

```bash
scripts/dev.sh          # Linux/macOS/WSL
.\scripts\dev.ps1       # Windows PowerShell
```

输出到 `dev/` 目录。

### 5.2 安装到思源

把 `dist/`（或 `dev/`）目录放入思源工作空间 `/data/plugins/` 下，命名为插件名目录（如 `siyuan-more-code-block-info`），然后在思源「设置 → 集市 → 已下载」中启用插件；或直接刷新思源。

开发时建议把 `dev/` 软链接到插件目录，保存代码后刷新页面即可看到效果。

## 6. 调试要点

- 打开思源开发者工具（`Ctrl/Cmd + Shift + I`），查看控制台日志，前缀为 `[more-code-block-info]`。
- 修改代码后重新构建，再刷新思源页面或禁用/启用插件。
- 若标题栏注入不生效，先确认代码块根元素为 `.code-block` 且带 `data-type="NodeCodeBlock"`。

## 7. 发布

发布到思源社区集市的完整流程（含集市规则、版本号、Release、`plugins.txt` PR、自动化与排错）见 **[发布指南](发布指南.md)**。

最小步骤：

1. 同步提升 `plugin.json` 与 `package.json` 的 `version`。
2. 运行 `scripts/build.ps1`（或 `scripts/build.sh`）生成 `package.zip`。
3. 推送 `v<version>` 标签，由 GitHub Actions 自动构建并创建 Release；也可手动创建 Release 并上传 `package.zip`。
4. 首次上架需向 `siyuan-note/bazaar` 提交 PR，在 **`plugins.txt`** 中新增一行 `Coshining/Siyuan-more-code-block-info`。

> 注意：集市索引文件是 `plugins.txt`，不是旧文档中的 `plugins.json`。

## 8. 代码约定

- 全程强类型，禁止 `any`（个别与第三方类型交互处如确需，需注释说明）。
- 单个 TS 文件不超过 300 行，每层目录文件数不超过 8 个。
- 日志统一走 `src/util/logger.ts`。

## 9. 生命周期与卸载还原

插件在 `onunload()` 中必须把运行期对宿主 DOM 的修改全部还原，否则禁用插件后会残留控件或样式。

当前由 `destroyObserver()` 统一完成：

1. 解绑 `loaded-protyle-*`、`destroy-protyle` 事件，断开所有 `MutationObserver`，并清空待执行的 `requestAnimationFrame` 调度。
2. `restoreCodeBlockHeaders(document)`：
   - 移除注入的 `.code-block-collapse`、`.code-block-name`、`.code-block-theme`；
   - 移除 `data-more-code-info`、`data-fold`、`data-code-theme`；
   - 还原语言标签的 `protyle-action--first` class。
3. `destroyAllThemeSelectors()`：关闭并移除可能挂到 `document.body` 的主题菜单，解绑其 `pointerdown` 监听。
4. `removeThemeStyles()`：删除 `code-theme-css-*` 样式，并阻止在途请求在卸载后继续注入。
5. `uninstallNameIsolation()` / `uninstallCaretGuard()`：解绑名称输入框的全局事件隔离、光标保护监听与聚焦轮询定时器。

块属性 `custom-code-block-name`、`custom-code-block-theme`、`custom-code-block-fold` 属于用户文档数据，**不要**在卸载时删除；重新启用插件时需要继续读取它们。

`destroy-protyle` 时只还原本编辑器内的代码块（`restoreCodeBlockHeaders(root)`），不清理全局主题样式与全局监听，因为其他编辑器仍在使用。

新增任何全局监听、`document.head` 样式或挂到 `body` 的浮层时，都要同时提供对应的卸载函数，并接入 `destroyObserver()`。
